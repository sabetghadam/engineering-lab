# Software Engineering

> Built from 25 years of hands-on experience across fintech, blockchain, and enterprise systems.

Software engineering is the discipline of designing, building, testing, evolving, and maintaining software systems.

This section focuses on the engineering practices that make software understandable, maintainable, reliable, and adaptable as requirements and systems change.

The goal is not to follow a fixed set of rules or patterns. Different problems require different approaches, and engineering decisions should consider context, constraints, complexity, and long-term consequences.

## Topics

This section covers practical software engineering topics such as:

* Clean Code
* Refactoring
* Technical Debt
* Maintainability
* Code Review
* Testing
* Error Handling
* Validation
* Dependency Management
* API Design
* Documentation
* Debugging
* Performance
* Reliability

Each topic may contain a combination of:

* **Documentation** — concepts, explanations, and practical guidance
* **Examples** — small examples that demonstrate a specific idea
* **Implementations** — runnable code in relevant languages and frameworks
* **Diagrams** — visual explanations where they improve understanding
* **Experiments** — isolated experiments used to investigate a technical question
* **Cases** — lessons and observations from real-world systems

Not every topic needs all of these components. The structure should follow the needs of the subject.

## Languages and Technologies

Examples and implementations may use different technologies, including:

* TypeScript / JavaScript
* Node.js
* NestJS
* C# / .NET
* ASP.NET Core
* SQL
* React
* Angular

The technology is secondary to the engineering problem being demonstrated. When the same concept is implemented in multiple technologies, the differences and trade-offs should be made explicit.

## Practical Approach

Where appropriate, topics should answer questions such as:

1. What problem does this practice address?
2. What approaches are commonly used?
3. Why do they work?
4. What are their limitations?
5. What alternatives exist?
6. What do they introduce?
7. How can the idea be implemented in real code?
8. When should the approach not be used?

The examples should remain small enough to understand while being realistic enough to demonstrate the engineering problem.

## Real-World Context

Some topics may reference lessons from real software systems built over 25 years across fintech, blockchain, trading systems, and enterprise platforms.

These examples are used to explain engineering problems and decisions rather than to present project portfolios.

Real-world material should clearly distinguish between:

* what was actually implemented
* what an implementation resembles conceptually
* what was learned from the implementation

Unverified details should not be presented as facts.

## Repository Principle

The examples in this section are intended to be practical and understandable.

Prefer a simple solution when it solves the problem.

Introduce additional abstraction, patterns, infrastructure, or distributed complexity only when there is a reason for them to exist.
